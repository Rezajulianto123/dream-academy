==================================================
BLOCKER 1 — ADMIN SEED SECURITY
==================================================

File:
prisma/seed-admin.ts

Masalah saat ini:

const email = process.env.ADMIN_EMAIL || 'admin@dreamacademy.id';
const password = process.env.ADMIN_PASSWORD || 'Admin123!';

Ini tidak acceptable karena terdapat fallback credential admin yang hardcoded.

Selain itu, mekanisme upsert saat ini selalu melakukan:

update: {
  role: 'admin',
  passwordHash,
}

Akibatnya menjalankan seed:admin berulang kali akan mengganti password admin.

PERBAIKI MENJADI:

1. ADMIN_EMAIL wajib berasal dari environment variable.
2. ADMIN_PASSWORD wajib berasal dari environment variable untuk provisioning awal.
3. Tidak boleh ada fallback email/password yang hardcoded.
4. Jika ADMIN_EMAIL tidak tersedia:
   - fail fast
   - tampilkan error yang jelas
   - jangan membuat atau mengubah user.
5. Jika ADMIN_PASSWORD tidak tersedia:
   - fail fast
   - tampilkan error yang jelas
   - jangan membuat atau mengubah user.
6. Jangan pernah log password atau passwordHash.
7. Password harus tetap di-hash menggunakan bcryptjs.
8. Provisioning harus idempotent secara operasional.

PENTING:

Jika user admin dengan email tersebut SUDAH ADA:
- pastikan role = admin
- JANGAN otomatis mengganti password existing user hanya karena seed:admin dijalankan ulang.

Jika user BELUM ADA:
- buat user admin menggunakan ADMIN_EMAIL dan ADMIN_PASSWORD.
- password di-hash menggunakan bcryptjs.

Tujuan:

Menjalankan:

ADMIN_EMAIL=admin@dreamacademy.id \
ADMIN_PASSWORD='strong-secret' \
npm run seed:admin

harus membuat admin baru.

Menjalankan command yang sama kembali tidak boleh menghasilkan user duplikat DAN tidak boleh merotasi password secara otomatis.

Jangan membuat sistem password reset baru.
Jangan membuat auth mechanism baru.
Jangan mengubah JWT Phase 1.
